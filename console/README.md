# 随笔浮想 · 桥接控制台（WinUI 3）

面向「随笔浮想」UGC 编辑器桥接工具链的**桌面可视化控制台**。所有与游戏内桥的通信
都复用既有 CLI 真源（`cli/fxapi.py` 等），本应用只做 GUI 编排，不另立协议。

## 启动

双击**仓库根目录**的 `启动控制台.cmd`（首次会自动 `dotnet build`，之后直接拉起已编译的 exe）。
或手动：

```powershell
dotnet build fuxiang-console.csproj -c Debug -p:Platform=x64
.\bin\x64\Debug\net8.0-windows10.0.19041.0\fuxiang-console.exe
```

首次启动会弹出「使用须知」风险确认（勾选「下次不再弹出」并确定后不再提示）；
需要装桥/重注入的权限说明见仓库根目录《请以管理员身份启动控制台.txt》。

前置：游戏已启动（装桥操作需在游戏进入编辑器后点总览页「安装 / 重注入桥接」，
普通终端会弹一次 UAC）。Python 解释器默认用
`<你的-python.exe-完整路径>`，
可在 `console/settings.json` 里用 `"Python"` 字段覆盖。

## 多桥接（多开游戏）

首页顶部「当前桥接」下拉框可在多条桥接间切换，所有页面操作（op、备份、截图、保存）都走当前选中的那条。
每条桥接的状态是各自独立看的（`主桥接 ● 在线 pid=21652`、`桥接2 ○ 未连接`），切换后首页会按那条通道的
真实状态重新给引导。要求多开游戏时每个客户端都各自运行；要让它连上，还得在那个窗口里进入编辑器。

- 「添加桥接…」：为另一个游戏窗口（pid）建立独立通道并注入桥。列表会把已经连着桥的窗口标成
  「（已有桥接）」并默认停在空闲的那个；硬选已占用的会被拦下（同一个游戏进程装两条桥会顶掉原连接）。
- 原理：工具链注入器支持 `ipc/install_override.json`（指定目标 pid + 独立通道目录）；应用会为每条额外桥接在
  `console/bridges/<名字>/` 克隆一份 `bridge/` + `cli/` + `mcp/` + `ipc/`，桥按自身脚本位置推导通道，互不干扰。
- 「移除当前」只从列表移除，不卸载游戏内的桥（重启游戏自然消失）。
- 用户可见的产物（备份、剧情/事件导出、物件标签、恢复进度、截图图库）都固定在**主工具根**
  （`snapshots/`、`projects/`、`builds/restore/`、`preview/shots/`），换到哪条桥接都不会散进通道目录。
- 工具根升级后，旧通道的克隆不会自动同步；遇到命令报错就「移除当前」再「添加桥接」重新克隆一次。

所有会改动地图的操作完成后都会弹「别忘了保存地图」，可选择立即保存（save_map+poll 编排）或稍后在游戏里保存。

## 结构

```
console/
  fuxiang-console.csproj    WinUI 3 unpackaged + WindowsAppSDKSelfContained
  App.xaml / MainWindow.xaml  NavigationView + Frame 导航；底部桥接状态 pill
  Pages/                    八个页面（XAML + code-behind）
  Services/
    Fx.cs     根定位、python 定位、桥接实例（当前选中的通道）、CallOp/Eval（进程调用该通道的
              cli/fxapi.py）、bridge_state 直读、SaveMapFlow、TeamAddSlot
    Bridges.cs 多桥接注册表与通道克隆、注入 override
    Cmds.cs   长任务 argv 构造（快照/剧情/事件/封面/截图/装桥）
    Job.cs    全局单任务运行器（逐行日志回调）
    Ui.cs     ContentDialog、日志框（有界缓冲+批量刷写、自动滚底）、文件列表、FileOpenPicker(HWND)
```

## 注意事项

- **保存纪律**：与工具链文档一致——每批摆放/还原完成后立即保存；`fuxiang_save_map`
  有单笔在途护栏；「保存会重置基线」。
- **写操作都有确认**：正式还原、删除槽位、上传封面、装桥均弹确认框；还原要求显式
  勾选确认。
- **任务串行**：桥按命令文件串行处理，GUI 侧同样全局一次只跑一个长任务。
- **「导出事件 / 生成物件标签 / 检查标签」在大图上很慢**：这些操作要逐件问一遍编辑器
  （实测约 200 件/70 秒，几千件要几十分钟，两万件的地图基本跑不完）。日志里会一行一行报进度
  （`…已读取 2000/3977`），不是在卡死；但普通使用不必点它们。
- **从 Git Bash 构建报 MSB3073/XamlCompiler exit 1**：Git Bash 的 `TEMP=/tmp` 会让
  旧版 XamlCompiler 静默失败；`启动控制台.cmd` 已内置修正 TEMP。另：本机缓存的
  windowsappsdk **1.8.250907003** 的 XamlCompiler 有此问题，**1.8.260804001** 正常
  （csproj 已固定后者）。
